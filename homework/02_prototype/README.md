# Домашнее задание №2. Создаем прототип продукта

## Проект: DeepFake-детекция для медиа-безопасности

---

### 1. Ключевая гипотеза

**Формат:**

> Если мы предлагаем **API для автоматической детекции deepfake-видео** для **онлайн-платформ с пользовательским видеоконтентом (UGC)** в сценарии **модерации загружаемых видео до публикации**, то мы получим **снижение доли мошеннического контента, прошедшего модерацию, на 40%** не менее чем за **3 месяца** тестовой эксплуатации, потому что **современные deepfake-видео визуально неотличимы от реальных для человека-модератора, но имеют выявляемые артефакты на уровне пикселей и во временной последовательности кадров**.

**Расшифровка гипотезы:**

| Компонент | Значение |
|-----------|----------|
| **Продукт A** | API для бинарной классификации видео (real/fake) с асинхронной обработкой |
| **Сегмент B** | Онлайн-платформы с UGC (видеохостинги, соцсети, образовательные платформы с видео-верификацией) |
| **Сценарий С** | Модерация видео до публикации (pre-moderation) + проверка уже опубликованного контента по запросу |
| **Метрика D** | Доля мошеннического deepfake-контента, не пропущенного модерацией (Recall по выявленным фейкам) |
| **Порог E** | Снижение на 40% (т.е. Recall ≥ 0.85 при текущем ручном Recall ~0.45) |
| **Время T** | 3 месяца тестовой эксплуатации на 3 платформах-партнёрах |

---

### 2. Ключевые метрики

#### Продуктовые метрики

| Метрика | Целевое значение | Способ измерения | Базовая линия (baseline) | Частота |
|---------|------------------|------------------|--------------------------|---------|
| **Recall (полнота)** по выявленным deepfake | ≥ 0.85 | A/B test: контрольная группа — ручная модерация, тестовая — API + ручная верификация спорных случаев | 0.45 (ручная модерация по данным заказчика) | Ежедневно |
| **Precision (точность)** | ≥ 0.80 | Доля правильных срабатываний API среди всех срабатываний | 0.60 (текущие сигнатурные методы) | Ежедневно |
| **Среднее время модерации одного видео** | Уменьшение на 60% (с 5 мин до 2 мин) | Замер времени от загрузки до решения | 5 минут (полный ручной цикл) | Еженедельно |
| **Доля видео, отправленных на ручную верификацию** | ≤ 20% | API возвращает confidence score; пограничные случаи (0.3-0.7) идут на проверку | 100% (сейчас все видео проверяют люди) | Ежедневно |

#### Технические (ML) метрики

| Метрика | Целевое значение | Способ измерения | Baseline | Частота |
|---------|------------------|------------------|----------|---------|
| **AUC** | ≥ 0.90 на FF++, ≥ 0.70 на Celeb-DF | Тест на отложенных выборках | Нет (с нуля) | После каждого обучения |
| **F1-score** | ≥ 0.85 на FF++ | Тест на отложенной выборке | Нет | После каждого обучения |
| **Latency (инференс на одно видео)** | ≤ 5 секунд (CPU) / ≤ 1 секунда (GPU) | Замер времени обработки видео длительностью 30 сек | — | Ежедневно в тесте |
| **Throughput (воркеров)** | ≥ 10 видео/минуту на 1 воркере (CPU) | Нагрузочное тестирование | — | При каждом релизе |
| **Memory usage (воркер)** | ≤ 2 GB RAM | Мониторинг ресурсов | — | При каждом релизе |

### 3. Что входит в прототип (In Scope)

| Компонент | Включено | Пояснение |
|-----------|----------|-----------|
| **Бинарная классификация** (Real/Fake) | ✅ | Основная бизнес-ценность |
| **Извлечение лиц из видео** | ✅ | Критично для работы модели |
| **Анализ временной последовательности** (CNN+LSTM) | ✅ | Без этого модель не увидит артефакты во времени |
| **API эндпоинт** `/predict_video` | ✅ | Принимает ссылку на видео, возвращает класс + confidence |
| **Асинхронная очередь задач** | ✅ | Для обработки длинных видео без блокировки |
| **Базовый веб-интерфейс** (для демо модератору) | ✅ | Чтобы заказчик мог протестировать вручную |
| **Логирование предсказаний** | ✅ | Для анализа ошибок и сбора данных |
| **Docker-контейнеризация** | ✅ | Для воспроизводимости и простоты развертывания |

---

### 4. Что НЕ входит в прототип (Out of Scope)

| Компонент | Не включено | Причина |
|-----------|-------------|---------|
| **Мультиклассовая детекция** (определение типа deepfake) | ❌ | Не критично для MVP, усложняет модель и датасеты |
| **Аудио-анализ** (проверка синхронизации звука) | ❌ | Сильно усложняет прототип, можно добавить позже |
| **Система биллинга/кредитов** | ❌ | Для прототипа не нужна; будет в продукте |
| **Поддержка потокового видео** (RTMP, HLS) | ❌ | Редкий сценарий, можно добавить позже |
| **Обучение на новых данных (online learning)** | ❌ | Требует сложной инфраструктуры, не для прототипа |
| **Face detection для нескольких лиц в кадре** | ❌ | Для MVP берём видео с одним лицом (или берём самое крупное) |
| **Мобильное приложение** | ❌ | API достаточно для интеграции |

### 5. Готовые блоки и инструменты

| Компонент | Что берём готовое | Что делаем сами | Почему |
|-----------|-------------------|-----------------|--------|
| **Face detection** | MTCNN / RetinaFace (готовые библиотеки) | — | Стабильные, быстрые, с открытым кодом |
| **CNN backbone** | EfficientNetB0 (предобученный на ImageNet) | — | Легковесный, высокая точность, transfer learning |
| **LSTM/GRU** | PyTorch `nn.LSTM` | Настройка архитектуры (размер hidden state, слои) | Гибкость в эксперименте |
| **Асинхронная очередь** | RabbitMQ + Celery | Конфигурация и интеграция | Стандарт индустрии |
| **API фреймворк** | FastAPI | — | Быстрый, асинхронный, с автоматической документацией |
| **База данных** | PostgreSQL | Схема таблиц (логи, метрики) | Надёжность, знакомая команде |
| **Контейнеризация** | Docker + Docker Compose | Dockerfile и docker-compose.yml | Воспроизводимость |
| **Обучение модели** | PyTorch + Albumentations | Pipeline обучения, цикл валидации | Полный контроль над моделью |
| **Визуализация метрик** | TensorBoard / MLflow | Настройка логирования | Отслеживание экспериментов |

**Критичное, что делаем сами:**
- **Pipeline предобработки видео** (извлечение кадров, crop лица, нормализация) — потому что готового решения для нашего формата входных данных нет.
- **Обучение CNN+LSTM** — потому что это ядро продукта и наша основная ML-ценность.
- **Интеграция модели в воркер** — чтобы связать ML с очередью и API.

### 6. Главный риск прототипа

| Риск | Описание | Как проверяем |
|------|----------|---------------|
| **Падение генерализации модели** | Модель, обученная на FaceForensics++, может плохо работать на реальных deepfake-видео от мошенников (которые используют новые методы). | Тестируем на Celeb-DF (другой домен). Если падение слишком сильное (AUC < 0.65) → риски высоки. |
| **Скорость инференса слишком низкая** | Обработка одного видео может занимать минуты вместо секунд, что сделает API бесполезным. | Нагрузочное тестирование: проверяем latency на CPU и GPU. |
| **Отсутствие чистых данных для обучения** | В датасетах могут быть артефакты сжатия, которые модель выучит, но они не будут в реальных данных. | Проверяем на валидационной выборке из другого датасета. |
| **Ложные срабатывания (false positive)** | Если модель часто ошибается на реальных видео, модераторы перестанут ей доверять. | Мониторим Precision; если <0.70 — останавливаем тест. |

### 7. Критерии остановки теста прототипа

Тест прототипа останавливается, если выполняется **хотя бы одно** из условий:

| Критерий | Значение | Действие |
|----------|----------|----------|
| **Recall < 0.60** на тестовой выборке из реальных видео | Модель пропускает >40% deepfake | Остановка, нужна новая архитектура |
| **Precision < 0.65** | Слишком много ложных срабатываний | Остановка, балансировка классов или порога |
| **Latency > 30 секунд** на видео длительностью 30 сек (CPU) | Медленная обработка | Остановка, нужна оптимизация (GPU, модель легче) |
| **AUC < 0.70** на Celeb-DF | Генерализация слишком слабая | Остановка, нужны новые данные или другой подход |
| **Доля ручной верификации > 50%** | API не снижает нагрузку на модераторов | Остановка, повышать confidence модели |
| **Заказчик не предоставил тестовые данные в течение 2 недель** | Нет возможности валидации | Приостановка до получения данных |

### 8. Конечный формат прототипа

**Вид прототипа:**  
Docker-контейнеризованный сервис с REST API.

**Что получает заказчик на выходе:**

1. **Docker-образ** с ML-сервисом (FastAPI + модель + воркеры)
2. **docker-compose.yml** для подъёма всего стека (API, PostgreSQL, RabbitMQ, воркеры)
3. **Документация API** (Swagger, доступная по `/docs`)
4. **Jupyter Notebook** с обучением модели и воспроизводимыми результатами
5. **Отчёт по метрикам** (AUC, F1, Precision, Recall на FF++ и Celeb-DF)
6. **Инструкция по развертыванию** (5-10 минут до первого запроса)

**Пример взаимодействия:**
```bash
# Запрос на предсказание
POST /api/v1/predict
{
  "video_url": "https://example.com/video.mp4",
  "callback_url": "https://client.com/webhook"  # опционально
}

# Ответ
{
  "task_id": "123e4567-e89b-12d3-a456-426614174000",
  "status": "queued"
}

# Через некоторое время по webhook:
{
  "task_id": "...",
  "prediction": "fake",
  "confidence": 0.94,
  "processing_time_sec": 4.2
}
