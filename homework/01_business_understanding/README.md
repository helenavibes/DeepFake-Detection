## 1. Бизнес-анализ (Business Understanding)

**Организационная структура:**
- Заказчик: отдел информационной безопасности / антифрод-подразделение
- Пользователи: модераторы видеоконтента, API внешних систем (автоматическая проверка видео)

**Бизнес-цель:**
Автоматическое обнаружение deepfake-видео для снижения мошеннических рисков и ускорения модерации видеоконтента.

**Существующие решения и их недостатки:**
| Решение | Недостатки |
|---------|-------------|
| Ручная модерация | Не масштабируется, дорого, медленно |
| Сигнатурные методы (метаданные, битрейт) | Не работают против новых deepfake-генераций |
| Open-source ноутбуки (GitHub) | Нет API, нет очередей, нет интеграции с бизнес-процессами |
| Коммерческие сервисы (Microsoft, Intel) | Закрытые, дорогие, не кастомизируются |

| **Модель не влезает в память GPU** | Средняя | Использовать batch size 8-16, mixed precision (fp16), градиентную аккумуляцию. Взять легковесную архитектуру (EfficientNetB0 вместо ResNet152). |
| **Deepfake-модель устареет** | Высокая (долгосрочно) | Предусмотреть регулярное дообучение (retraining) на новых датасетах. Мониторинг качества модели в production. |

## 1.2 Решаемые задачи (Data Mining goals)

**Тип задачи:**
- **Бинарная классификация** видео: Real (0) vs Fake (1)

**Входные данные (после предобработки):**
- Клип из 10–30 последовательных кадров видео
- Кадры обрезаны до лица (face crop), размер 224×224 пикселя

**Метрики качества:**

| Метрика | Почему выбрана |
|---------|----------------|
| **AUC** | Главная метрика. Устойчива к дисбалансу классов. Позволяет оценить разделяющую способность модели. |
| **F1-score** | Баланс между точностью и полнотой. Важен для несбалансированных данных. |
| **Precision** | Важен для бизнеса: минимизация ложных срабатываний (не ошибочно блокировать реальные видео). |
| **Recall** | Важен для безопасности: найти максимум фейков (не пропустить мошенническое видео). |

**Критерии успешности модели:**

| Этап | AUC | F1 | Precision | Recall |
|------|-----|----|-----------|--------|
| **Минимальный порог (in-domain)** | ≥ 0.75 | ≥ 0.70 | ≥ 0.70 | ≥ 0.70 |
| **Целевой порог (in-domain)** | ≥ 0.90 | ≥ 0.85 | ≥ 0.85 | ≥ 0.85 |
| **Cross-domain (Celeb-DF)** | ≥ 0.70 | ≥ 0.65 | ≥ 0.65 | ≥ 0.65 |
| **Production (мониторинг)** | TBD (сбор после внедрения) | TBD | TBD | TBD |

**Ожидаемый результат по генерализации:**
- Обучение на FaceForensics++ → AUC ~0.90-0.93
- Тест на Celeb-DF (без дообучения) → ожидаемое падение до AUC ~0.70-0.75
- **Этот разрыв будет задокументирован как ключевой вывод проекта**

## ⚠️ Этика, лицензии и мониторинг

### Лицензии датасетов
| Датасет | Лицензия | Ограничения |
|---------|----------|-------------|
| FaceForensics++ | CC BY-NC 4.0 | Только некоммерческое использование |
| Celeb-DF | Research only | Только исследовательские цели |
| DFDC | Facebook Research License | Не использовать для создания deepfake |

### Биометрия и приватность
- В проекте используются **только обезличенные наборы лиц** из открытых датасетов
- Реальная биометрия клиентов **не собирается и не хранится** без явного согласия
- Все лица в датасетах получены от согласных субъектов (актёры, публичные персоны)

### Риски двойного использования
- Модель может быть использована злоумышленниками для проверки своих deepfake
- **Контрмеры:** логирование всех запросов к API, аудит доступа, водяные знаки на выгрузках

### Мониторинг после внедрения
| Что мониторим | Как | Частота |
|---------------|-----|---------|
| Точность модели на новых видео | Сбор обратной связи от модераторов | Еженедельно |
| Дрейф данных (data drift) | Сравнение распределений признаков | Ежемесячно |
| Устаревание модели | Регулярный тест на свежих deepfake | Ежеквартально |
